# 回测

本页说明如何通过回测来验证您的策略表现。

回测需要有历史数据可用。
要了解如何获取您感兴趣的交易对和交易所的数据，请前往文档的[数据下载](data-download.md)部分。

回测也可以在[网页服务器模式](freq-ui.md#backtesting)下使用，允许您通过网页界面运行回测。

## 使用回测测试您的策略

现在您有了良好的入场和出场策略以及一些历史数据，您想要用真实数据来测试它。这就是我们所说的[回测](https://en.wikipedia.org/wiki/Backtesting)。

回测将使用您配置文件中的加密货币（交易对），默认从 `user_data/data/<exchange>` 加载历史K线（OHLCV）数据。
如果该交易所/交易对/时间周期组合没有可用数据，回测会要求您先使用 `freqtrade download-data` 下载数据。
有关下载的详细信息，请参阅文档中的[数据下载](data-download.md)部分。

回测结果将确认您的机器人盈利的可能性是否大于亏损。

所有利润计算都包含手续费，freqtrade 将使用交易所的默认手续费进行计算。

!!! Warning "使用动态交易对列表进行回测"
    可以使用动态交易对列表（并非所有处理器都允许在回测模式下使用），但它依赖于当前的市场条件——这不会反映交易对列表的历史状态。
    此外，当使用 StaticPairlist 以外的交易对列表时，无法保证回测结果的可重复性。
    请阅读[交易对列表文档](plugins.md#pairlists)获取更多信息。

    要获得可重复的结果，最好通过 [`test-pairlist`](utils.md#test-pairlist) 命令生成交易对列表，并将其用作静态交易对列表。

!!! Note
    默认情况下，Freqtrade 会将回测结果导出到 `user_data/backtest_results`。
    导出的交易记录可用于[进一步分析](#further-backtest-result-analysis)，或可被 scripts 目录中的[绘图子命令](plotting.md#plot-price-and-indicators)（`freqtrade plot-dataframe`）使用。


### 起始余额

回测需要一个起始余额，可以通过 `--dry-run-wallet <balance>` 或 `--starting-balance <balance>` 命令行参数提供，也可以通过 `dry_run_wallet` 配置设置提供。
此金额必须高于 `stake_amount`，否则机器人将无法模拟任何交易。

### 动态下注金额

回测支持[动态下注金额](configuration.md#dynamic-stake-amount)，通过将 `stake_amount` 配置为 `"unlimited"` 来实现，这将把起始余额分成 `max_open_trades` 份。
早期交易的利润将导致后续更高的下注金额，从而在回测期间产生复利效果。

### 回测命令示例

使用5分钟K线（OHLCV）数据（默认）

```bash
freqtrade backtesting --strategy AwesomeStrategy
```

其中 `--strategy AwesomeStrategy` / `-s AwesomeStrategy` 指的是策略的类名，该类位于 `user_data/strategies` 目录中的 Python 文件中。

---

使用1分钟K线（OHLCV）数据

```bash
freqtrade backtesting --strategy AwesomeStrategy --timeframe 1m
```

---

提供自定义起始余额1000（以计价货币计）

```bash
freqtrade backtesting --strategy AwesomeStrategy --dry-run-wallet 1000
```

---

使用不同的磁盘历史K线（OHLCV）数据源

假设您从 Binance 交易所下载了历史数据并保存在 `user_data/data/binance-20180101` 目录中。
您可以按如下方式使用此数据进行回测：

```bash
freqtrade backtesting --strategy AwesomeStrategy --datadir user_data/data/binance-20180101
```

---

比较多个策略

```bash
freqtrade backtesting --strategy-list SampleStrategy1 AwesomeStrategy --timeframe 5m
```

其中 `SampleStrategy1` 和 `AwesomeStrategy` 指的是策略的类名。

---

阻止将交易记录导出到文件

```bash
freqtrade backtesting --strategy backtesting --export none --config config.json
```

仅在您确定不需要绘图或进一步分析结果时才使用此选项。

---

导出交易记录到文件并指定自定义目录

```bash
freqtrade backtesting --strategy backtesting --export trades --backtest-directory=user_data/custom-backtest-results
```

---

请同时阅读关于[策略启动期](strategy-customization.md#strategy-startup-period)的内容。

---

提供自定义手续费值

有时您的账户有某些手续费返还（从特定账户规模或月交易量开始的手续费减免），这些对 ccxt 不可见。
为了在回测中考虑这一点，您可以使用 `--fee` 命令行选项向回测提供此值。
此手续费必须是比率，将被应用两次（一次用于交易入场，一次用于交易出场）。

例如，如果每笔订单的手续费率为0.1%（即以比率表示为0.001），则您可以按如下方式运行回测：

```bash
freqtrade backtesting --fee 0.001
```

!!! Note
    仅在您想要试验不同手续费值时才提供此选项（或相应的配置参数）。默认情况下，回测从交易所的交易对/市场信息中获取默认手续费。

---

使用时间范围缩小测试集运行回测

使用 `--timerange` 参数来更改要使用的测试集范围。

例如，使用 `--timerange=20190501-` 选项运行回测将使用输入数据中从2019年5月1日起的所有可用数据。

```bash
freqtrade backtesting --timerange=20190501-
```

您也可以指定特定的日期范围。

完整的时间范围规范：

- 使用截至2018/01/31的数据：`--timerange=-20180131`
- 使用2018/01/31起的数据：`--timerange=20180131-`
- 使用2018/01/31至2018/03/01的数据：`--timerange=20180131-20180301`
- 使用 POSIX / epoch 时间戳 1527595200 到 1527618600 之间的数据：`--timerange=1527595200-1527618600`

### 回测报告表

第一个表格包含机器人所做的所有交易，包括"未平仓交易"。

最后一行将给出您策略的整体表现，
如下：

```
│         TOTAL │     77 │         0.22 │          54.774 │         5.48 │        22:12:00 │   67     0    10  87.0 │
```

机器人共进行了 `77` 笔交易，平均持续时间为 `22:12:00`，表现为 `5.48%`（盈利），这意味着以1000 USDT的初始资金，总共赚取了 `54.774 USDT`。

`Avg Profit %` 列显示所有交易的平均利润。
`Tot Profit %` 列则显示相对于起始余额的总利润百分比。

在上述结果中，我们的起始余额为1000 USDT，绝对利润为54.774 USDT——所以 `Tot Profit %` 为 `(54.774 / 1000) * 100 ~= 5.48%`。

您的策略表现受到入场策略、出场策略以及您设置的 `minimal_roi` 和 `stop_loss` 的影响。

例如，如果您的 `minimal_roi` 仅为 `"0":  0.01`，您不能期望机器人获得超过1%的利润（因为它每次交易达到1%时就会退出）。

```json
"minimal_roi": {
    "0":  0.01
},
```

另一方面，如果您设置了过高的 `minimal_roi`，如 `"0":  0.55`（55%），机器人几乎没有机会达到这个利润。
因此，请记住，您的表现是策略所有不同元素、配置以及您设置的加密货币交易对的综合结果。

### 未平仓交易表

第二个表格包含机器人在回测期结束时必须 `force_exit`（强制退出）的所有交易，以便向您展示完整的情况。
这对于模拟真实行为是必要的，因为回测期必须在某个时间点结束，而在现实中，您可以让机器人永远运行。
这些交易也包含在第一个表格中，但为了清晰起见，在此表格中单独显示。

### 入场标签统计表

第三个表格按入场标签（例如 `enter_long`、`enter_short`）对交易进行分类，显示入场次数、平均利润百分比、计价货币总利润、总利润百分比、平均持续时间以及每个标签的盈/平/亏次数。

### 出场原因统计表

第四个表格包含出场原因的汇总（例如 `exit_signal`、`roi`、`stop_loss`、`force_exit`）。此表格可以告诉您哪些方面需要额外改进（例如，如果许多 `exit_signal` 交易是亏损的，您应该改进出场信号或考虑禁用它）。

### 混合标签统计表

第五个表格结合了入场标签和出场原因，提供了不同入场标签在特定出场原因下表现的详细视图。这可以帮助识别哪些入场和出场策略的组合最有效。

### 回测结果缓存

为了节省时间，默认情况下，当回测的策略和配置与之前的回测匹配时，回测将重用一天内的缓存结果。要在存在相同运行结果的情况下强制进行新的回测，请指定 `--cache none` 参数。

!!! Warning
    对于开放式时间范围（`--timerange 20210101-`），缓存会自动禁用，因为 freqtrade 无法可靠地确保底层数据没有更改。如果原始回测在末尾缺少数据，而后来通过下载更多数据修复了此问题，它也可能在不应该使用缓存结果时使用了缓存结果。
    在这种情况下，请使用 `--cache none` 一次以强制进行全新回测。

## 回测的假设

由于回测缺乏关于K线内价格变动的详细信息，它需要做出一些假设：

- 遵守交易所的[交易限制](#trading-limits-in-backtesting)
- 除非指定了自定义价格逻辑，否则入场在开盘价发生
- 只要价格在K线的最高/最低范围内，所有订单都以请求的价格成交（无滑点）
- 出场信号触发的退出在下一根K线的开盘价发生
- 退出后释放交易槽位以便用不同的交易对进行新交易
- 出场信号优先于止损，因为出场信号被假定在K线开盘时触发
- ROI
  - 退出与最高价比较——但使用 ROI 值（例如 ROI = 2%，最高 = 5% - 所以退出将在2%）
  - 退出永远不会"低于K线"，所以2%的 ROI 可能会在2.4%退出（如果最低点在2.4%利润处）
  - 在触发K线上生效的 ROI 条目（例如1小时K线的 `120: 0.02`，来自 `60: 0.05`）将使用K线的开盘价作为退出价格
  - 由 `<N>=-1` ROI 条目引起的强制退出使用最低价作为退出值，除非 N 恰好在K线开盘时（例如1小时K线的 `120: -1`）
- 止损退出恰好在止损价格发生，即使最低价更低，但损失将比止损价格高 `2 * fees`
- 止损在一根K线内先于 ROI 评估。因此，与在模拟/实盘交易模式下使用相同策略获得的结果相比，您通常会看到更多以 `stoploss` 为退出原因的交易
- 对于止损，最低价先于最高价发生，优先保护资金
- 追踪止损
  - 追踪止损仅在低于K线最低价时才会调整（否则会被触发）
  - 在触发追踪止损的交易入场K线上，假设使用"最小偏移量"（`stop_positive_offset`）（而非最高价）——止损从该点计算。此规则不适用于自定义止损场景，因为没有关于止损逻辑的可用信息。
  - 最高价先发生——调整止损
  - 最低价使用调整后的止损（因此具有较大最高-最低差异的退出可以被正确回测）
  - ROI 先于追踪止损应用，确保当 ROI 和追踪止损都适用时，利润在 ROI 处"封顶"
- 退出原因不说明交易是盈利还是亏损，只说明什么触发了退出（如果使用负 ROI 值，这可能看起来很奇怪）
- 评估顺序（如果多个信号在同一根K线上发生）
  - 出场信号
  - 止损
  - ROI
  - 追踪止损
- 仓位反转（仅限期货）在现有交易平仓的K线上，如果另一方向的入场信号触发，则会发生反转。

基于这些假设，回测尽可能地模拟真实交易。然而，回测**永远**无法替代在模拟模式下运行策略。
同时，请记住，过去的结果不保证未来的成功。

除了上述假设外，策略作者应仔细阅读[常见错误](strategy-customization.md#common-mistakes-when-developing-strategies)部分，以避免在回测中使用在真实市场条件下不可用的数据。

### 回测中的交易限制

交易所有特定的交易限制，如最小（和最大）基础货币，或最小/最大下注（报价）货币。
这些限制通常列在交易所文档中的"交易规则"或类似部分，不同交易对之间可能差异很大。

回测（以及实盘和模拟运行）遵守这些限制，并将确保止损可以设置在此值以下——因此该值将略高于交易所指定的值。
然而，Freqtrade 没有历史限制的信息。

这可能导致使用历史价格时交易限制被抬高，导致最低金额大于50\$的情况。

例如：

BTC 最小可交易数量为0.001。
BTC 今天的交易价格为22,000\$（0.001 BTC 与此相关）——但回测期间包含高达50,000\$的价格。
今天的最低限额将是 `0.001 * 22_000` - 即22\$。
然而在某些历史设置中，限额也可能是50$ - 基于 `0.001 * 50_000`。

#### 交易精度限制

大多数交易所对价格和数量都有精度限制，因此您不能买入1.0020401个交易对，或以1.24567123123的价格买入。
相反，这些价格和数量将被四舍五入或截断（根据交易所定义）到定义的交易精度。
上述值可能例如被四舍五入为数量1.002和价格1.24567。

这些精度值基于当前的交易所限制（如[上述部分](#trading-limits-in-backtesting)所述），因为历史精度限制不可用。

## 提高回测精度

回测的一个重大限制是无法知道K线内价格的变动方式（最高价是在收盘价之前还是之后？）。
因此，假设您使用1小时时间周期运行回测，该K线将有4个价格（开盘价、最高价、最低价、收盘价）。

虽然回测确实对此做了一些假设（请阅读上文）——但这永远不可能完美，总是会在某一方面存在偏差。
为了缓解这一问题，freqtrade 可以使用更低（更快）的时间周期来模拟K线内的变动。

要使用此功能，您可以在常规回测命令后附加 `--timeframe-detail 5m`。

``` bash
freqtrade backtesting --strategy AwesomeStrategy --timeframe 1h --timeframe-detail 5m
```

这将为选定的时间范围加载1小时数据（主时间周期）和5分钟数据（详细时间周期）。
策略将使用1小时时间周期进行分析。
可能发生交易活动的K线（有活跃信号、交易对处于交易中）将在5分钟时间周期上进行评估。
这将允许更准确地模拟K线内变动——并可能导致不同的结果，尤其是在更高的时间周期上。

入场通常仍然在主K线的开盘价发生，但释放的交易槽位可能会更早释放（如果出场信号在5分钟K线上触发），然后可以用于不同交易对的新交易。

所有回调函数（`custom_exit()`、`custom_stoploss()` 等）将在交易开仓后为每根5分钟K线运行一次（因此在上述1小时时间周期和5分钟详细时间周期的示例中为12次）。

`--timeframe-detail` 必须小于原始时间周期，否则回测将无法启动。

显然，这将需要更多内存（5分钟数据比1小时数据大），也会影响运行时间（取决于交易数量和交易持续时间）。
此外，数据必须已经可用/已下载。

!!! Tip
    您可以将此功能作为策略开发的最后一步，以确保您的策略没有利用[回测假设](#assumptions-made-by-backtesting)中的某一项。在此模式下表现同样良好的策略在模拟/实盘模式下也有很好的表现机会（尽管只有前向测试（模拟模式）才能真正确认一个策略）。

??? Sample "极端差异示例"
    在极端示例上使用 `--timeframe-detail`（以下所有交易对在10:00的K线上都有入场信号）可能导致以下回测交易序列（max_open_trades 为1）：

    | Pair | Entry Time | Exit Time | Duration |

    | BTC/USDT | 2024-01-01 10:00:00 | 2021-01-01 10:05:00 | 5m |
    | ETH/USDT | 2024-01-01 10:05:00 | 2021-01-01 10:15:00 | 10m |
    | XRP/USDT | 2024-01-01 10:15:00 | 2021-01-01 10:30:00 | 15m |
    | SOL/USDT | 2024-01-01 10:15:00 | 2021-01-01 11:05:00 | 50m |

## 回测多个策略

要比较多个策略，可以向回测提供策略列表。

每次运行限制为1个时间周期值。但是，数据只从磁盘加载一次，因此如果您有多个
策略要比较，这将提供良好的运行时间提升。

所有列出的策略需要在同一目录中，除非同时指定了 `--recursive-strategy-search`，在这种情况下也会考虑策略目录中的子目录。

``` bash
freqtrade backtesting --timerange 20180401-20180410 --timeframe 5m --strategy-list Strategy001 Strategy002 --export trades
```

这将把结果保存到 `user_data/backtest_results/backtest-result-<datetime>.json`，包含 `Strategy001` 和 `Strategy002` 的结果。
将有一个额外的表格比较不同策略的盈亏情况（与第一个表格中的"Total"行相同）。
所有策略的详细输出将依次提供，因此请确保向上滚动以查看每个策略的详细信息。

