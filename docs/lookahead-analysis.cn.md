# 前瞻分析

本页面解释了如何验证您的策略是否存在前瞻偏差。

前瞻偏差是任何策略的大敌，因为它有时非常容易引入，但很难检测。

回测在初始化时加载所有时间戳（将整个数据帧加载到内存中）并一次性计算所有指标。
这意味着如果您的指标或入场/出场信号查看了未来蜡烛的数据，这将使您的回测结果失真。

`lookahead-analysis` 命令需要历史数据可用。
要了解如何获取您感兴趣的交易对和交易所的数据，
请前往文档的[数据下载](data-download.md)部分。
`lookahead-analysis` 也支持 freqai 策略。

此命令在内部串联回测并探测策略以引发其显示前瞻偏差。
这不是通过查看策略代码本身来完成的，而是通过比较与完整回测相比指标值的变化和入场/出场的移动来实现的。

`lookahead-analysis` 可以使用[回测](backtesting.md)的典型选项，但强制使用以下选项：

- `--cache` 被强制设置为 "none"。
- `--max-open-trades` 被强制设置为至少等于交易对的数量。
- `--dry-run-wallet` 被强制设置为基本上无限大（10 亿）。
- `--stake-amount` 被强制设置为静态的 10000（1 万）。
- `--enable-protections` 被强制关闭。
- `order_types` 被强制设置为 "market"（延迟入场），除非设置了 `--lookahead-allow-limit-orders`。

这些设置是为了避免用户意外产生误报。

### 介绍

许多策略在程序员不知情的情况下已经成为前瞻偏差的受害者。
这通常使策略回测看起来有利可图，有时甚至极端地好，但这并不真实，因为策略通过查看在模拟或实盘模式下不会拥有的数据来"作弊"。

策略能够"作弊"的原因是 freqtrade 回测过程在一开始就填充了包含所有蜡烛时间戳的完整数据帧。
如果程序员不小心或不了解内部工作原理
（这有时确实很难弄清楚），那么策略就会查看未来的数据。

此命令旨在尝试验证上述前瞻偏差形式的有效性。

### 命令如何工作？

它将从对所有交易对的回测开始，以生成指标和入场/出场的基准。
在此初始回测运行之后，它会检查 `minimum-trade-amount` 是否满足，如果不满足，则取消对该策略的前瞻分析。
如果发生这种情况，请使用更宽的时间范围以获取更多交易用于分析，或使用更多交易发生的时间范围。

设置基准后，将对每个入场和出场分别进行额外的回测运行。
当这些验证回测完成后，将比较两个数据帧（基准和切片）的列值差异，并报告偏差。
在所有信号被验证或证伪后，将为用户生成结果表。

### 如何发现和消除偏差？如何挽救有偏差的策略？

如果您在网上找到了一个有偏差的策略并希望获得相同的结果但没有偏差，
那么大多数时候您将无法如愿。
通常策略中的偏差是"好得令人难以置信"利润的主要驱动因素。
移除由偏差推动利润上升的条件或指标通常会使策略显著变差。
如果有偏差的指标或条件不是策略的核心，或者有其他不带偏差的入场和出场信号，您可能能够部分挽救它。

### 前瞻偏差的示例

- `shift(-10)` 查看了未来 10 根蜡烛。
- 在 populate_* 函数中使用 `iloc[]` 访问数据帧中的特定行。
- for 循环容易引入前瞻偏差，如果您没有严格控制循环的数字范围。
- 聚合函数如 `.mean()`、`.min()` 和 `.max()`，如果没有滚动窗口，
  将在**整个**数据帧上计算值，因此信号蜡烛将"看到"包含未来蜡烛的值。
  一个无偏差的示例是使用 `rolling()` 回看蜡烛：
  例如 `dataframe['volume_mean_12'] = dataframe['volume'].rolling(12).mean()`
- `ta.MACD(dataframe, 12, 26, 1)` 当 signalperiod 为 1 时会引入偏差。

### 结果表中的列是什么意思？

- `filename`：被检查的策略文件名
- `strategy`：被检查的策略类名
- `has_bias`：前瞻分析的结果。`No` 表示良好，`Yes` 表示有问题。
- `total_signals`：检查的信号数量（默认为 20）
- `biased_entry_signals`：在那么多入场中发现了偏差
- `biased_exit_signals`：在那么多出场中发现了偏差
- `biased_indicators`：显示在 populate_indicators 中定义的有偏差的指标本身

如果您有带偏差的入场信号与那些出场配对，您可能会在 `biased_exit_signals` 中得到误报。
然而，有偏差的入场通常也会导致有偏差的出场，
即使出场本身不产生偏差 -
特别是如果您的入场和出场条件使用相同的有偏差指标。

**先解决入场中的偏差，然后再解决出场中的偏差。**

### 注意事项

- `lookahead-analysis` 只能验证/证伪它计算和验证过的交易。
如果策略有许多不同的信号/信号类型，您需要选择适当的参数以确保所有信号至少触发过一次。未触发的信号将不会被验证。
这将导致假阴性，即策略将被报告为无偏差。
- `lookahead-analysis` 可以使用相同的回测选项，这可能会引入问题。
请不要使用启用仓位叠加等选项，因为这会扭曲检查的信号数量。
如果您决定这样做，请务必确保您不会耗尽 `max_open_trades` 插槽，
并且回测钱包配置中有足够的资金。
- 限价单与 `custom_entry_price()` 和 `custom_exit_price()` 回调的组合可能导致延迟入场和出场，从而产生误报。
为避免这种情况 - 此命令强制使用市价单。这隐含地意味着 `custom_entry_price()` 和 `custom_exit_price()` 回调不会被调用。
使用 `--lookahead-allow-limit-orders` 将跳过覆盖并使用您配置的订单类型 - 但已显示最终会产生误报。
- 在结果表中，`biased_indicators` 列
会错误地将 `set_freqai_targets()` 中定义的 FreqAI 目标指标标记为有偏差。
**这些并非有偏差的，可以安全地忽略。**
